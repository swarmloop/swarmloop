## Reading with a reader

- Ask narrow questions that name the files, the symbols and what you need from them, never a summary of a module.
- Ask everything that is independent in one call.
- When you need all of something (every caller, every file that holds X), ask for the full list with the search that made it.
- When an answer is vague, partial or marked as an inference, ask again more narrowly. Never fill the gap yourself.
- Check a fact a decision rests on (a file the plan lists, a call it changes, a behaviour it keeps) by its quote, with one search for the quoted line, and never by rereading the file. A confident but wrong answer is caught this way too.

Hand the reading to the reader. Read yourself only to settle a doubt: a quote is missing, vague or marked as an inference, two facts disagree, or a decision rests on the fact and the reader's second, narrower answer did not settle it. Then read only the lines that settle it, the quoted range and the function around it, never a file or a search sweep the reader could do.

Without a reader you read yourself. The decisions, the actions and the result block are yours.

# Live places

Every screen part that follows the socket, the events it follows, where the client applies them, what it reads again on a
reconnect, and the spec that proves it against the real gateway. Server specs boot `createTestApp({ socket: true })` and
drive it with the clients of `server/src/testing/live-clients.spec-helpers.ts`; dashboard tests use the fake socket.

| Screen part                                           | Socket events                                                    | What the client applies (file)                                                         | What it reads again on reconnect                                                           | Spec                                                                                               |
| ----------------------------------------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Sidebar run list, Active, no filter                   | `runs` (on connect), `run`                                       | `use-live-bridge.ts` (`onRuns`, `onRun`) with `apply-run-change.ts`                    | `use-runs.ts` reads the shown part and filter again                                        | `server/src/testing/live-list.e2e.spec.ts` (a, d), `features/runs/use-runs.test.tsx`               |
| Sidebar run list, Done, All, and Active with a filter | `run` (the `runs` page is ignored)                               | `use-live-bridge.ts` (`onRun`) with `apply-run-change.ts`; the view filters the rows   | `use-runs.ts` reads the shown part and filter again                                        | `server/src/testing/live-list.e2e.spec.ts` (b, c)                                                  |
| Part counts (Active, Done, All)                       | `runs`, `run` (`counts`)                                         | `use-live-bridge.ts` (`counts`)                                                        | the `runs` page of the connect carries the counts; `use-runs.ts` reads the list            | `server/src/testing/live-shell.e2e.spec.ts`                                                        |
| Run page header (status, step, tokens, cost)          | `flow` (and, once `usage` exists, `usage`)                       | `use-live-bridge.ts` (`onFlow`), `features/run/use-run-flow.ts`                        | `watch` is sent again on connect and the server answers with the `flow`; `use-run-flow.ts` | `server/src/testing/live-run-page.e2e.spec.ts`                                                     |
| Board and phases                                      | `flow`                                                           | `use-run-flow.ts` (`phases`)                                                           | the `flow` the server sends on `watch`                                                     | `server/src/testing/live-run-page.e2e.spec.ts`                                                     |
| Step window                                           | `flow` (the `revision` moves the step read), `log`               | `features/run/use-step.ts`                                                             | the `flow` on `watch` moves the revision, so the step is read again                        | `server/src/testing/live-run-page.e2e.spec.ts`                                                     |
| Checks (command lines)                                | `log` with `command`, `flow` (`checkCommands`)                   | `use-live-bridge.ts` (`onLog`), `features/run/flow/step-detail/check-command-line.tsx` | the `flow` on `watch`; the step read                                                       | `server/src/testing/live-run-page.e2e.spec.ts`                                                     |
| Conversation                                          | `flow` (`conversation`)                                          | `use-run-flow.ts`                                                                      | the `flow` on `watch`                                                                      | `server/src/testing/live-run-page.e2e.spec.ts`                                                     |
| Tasks of an epic                                      | `flow` of the epic: the epic's own change and a subtask's change | `use-run-flow.ts` (`tasks`, `taskLine`)                                                | the `flow` on `watch`                                                                      | `server/src/testing/live-epic.e2e.spec.ts`                                                         |
| Epic ETA and epic cost                                | `flow` of the epic: the epic's own change and a subtask's change | `use-run-flow.ts` (`eta`, `epic`)                                                      | the `flow` on `watch`                                                                      | `server/src/testing/live-epic.e2e.spec.ts`                                                         |
| Logs                                                  | `log`                                                            | `use-live-bridge.ts` (`onLog`), `use-step.ts`                                          | none: a log is not stored by the socket; the step read gives the stored one                | `server/src/testing/live-run-page.e2e.spec.ts`                                                     |
| Events timeline                                       | `events` (one per run per 500 ms window)                         | `use-live-bridge.ts` (`onEvents`), `features/run/transcript/use-step-events.ts`        | `use-step-events.ts` reads after the last held `seq`                                       | `server/src/testing/live-run-page.e2e.spec.ts`, `features/run/transcript/use-step-events.test.tsx` |
| Overview figures and parts                            | `run` rows laid over the reads, `statusStamp`                    | `features/overview/use-overview-runs.ts`, `features/stats/use-stats-version.ts`        | the `runs` page and the counts of the connect change the version, so both reads run again  | `server/src/testing/live-shell.e2e.spec.ts`                                                        |
| Stats                                                 | `run` (`statusStamp`, counts)                                    | `features/stats/use-stats-version.ts`                                                  | the `runs` page and the counts of the connect change the version                           | `server/src/testing/live-shell.e2e.spec.ts`                                                        |
| Backlog page                                          | `backlog`, `run` rows with a label (backlog stamp)               | `use-live-bridge.ts` (`backlogStamps`), `features/backlogs/use-backlog.ts`             | `use-backlog.ts` reads the backlog and its chat again                                      | `server/src/testing/live-shell.e2e.spec.ts`, `features/backlogs/backlog-screen.test.tsx`           |
| Backlog list                                          | `backlog`, `run` rows with a label (backlog stamp)               | `use-live-bridge.ts` (`backlogStamps`), `features/backlogs/use-backlogs.ts`            | `use-backlogs.ts` reads the list again                                                     | `server/src/testing/live-shell.e2e.spec.ts`, `features/backlogs/backlog-list.test.tsx`             |
| Pause banner                                          | `server` (also sent on every connect)                            | `use-live-bridge.ts` (`onServer`), `features/shell/pause-banner.tsx`                   | the `server` state the server sends on connect                                             | `server/src/testing/live-shell.e2e.spec.ts`                                                        |

The elapsed time of an open step is not sent: the client counts it from `stepStartedAt` of the run page.

Nothing else updates live.
